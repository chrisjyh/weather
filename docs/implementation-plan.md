# 구현 계획

## 목표

기존 차량 문 제어 예제를 실제 위치와 기상청 데이터를 사용하는 차량용 날씨 MVP로 전환합니다.
Kotlin·Jetpack Compose와 기존 applicationId, 빌드 도구 버전을 유지하며
Clean Architecture와 MVVM을 `app / domain / data` 세 모듈로 구성합니다.

최종 완료 기준은 Pleos 에뮬레이터에서 **실제 기상청 날씨를 표시**하고,
창 크기·주행 제한·네트워크·위치 권한 변경에도 화면과 상태를 올바르게 유지하는 것입니다.
현재 구현 완료 항목과 이 최종 완료 기준의 충족 여부는 별개입니다.

## MVP 범위

| 포함 | 제외 |
|---|---|
| 현재 위치와 마지막/기본 위치 fallback | 지역 검색, 즐겨찾기, 목적지 날씨 |
| 현재 기온·날씨, 오늘 공식 최고·최저 | 체감 온도, 단위 설정 |
| 강수 확률·예상 강수량, 향후 6시간 예보 | 기상 특보, 음성 안내 |
| 새로고침, 영속 캐시, 자료 시각·오래됨 표시 | 로그인, 서버 구축 |
| 주·야간, 좁은/넓은 창, 주행 간소화 | 스토어 출시, 주행 중 실행 승인 |
| 로딩·권한·오프라인·부분 실패·오류 | 디자인 예시의 바람·습도·일몰 표시 |

## 주요 결정

- 모듈 의존성은 `app → domain`, `app → data`, `data → domain`으로 제한합니다.
- domain은 Android, Compose, 기상청 DTO, 차량 SDK를 참조하지 않습니다.
- Coroutines/Flow와 불변 StateFlow를 사용하고 생명주기에 맞춰 구독합니다.
- AppContainer와 ViewModel Factory로 생성자 주입합니다. 별도 DI 프레임워크나 공통 Base 클래스는 추가하지 않습니다.
- 네트워크는 Retrofit/OkHttp, 파싱은 Kotlin Serialization, 영속 캐시는 Room입니다.
- 위치는 Android LocationManager를 사용합니다. Google Play Services와 백그라운드 위치 권한은 사용하지 않습니다.
- 주행 판단은 CarUxRestrictions를 사용하며 속도·기어로 별도 추정하지 않습니다.
- 기존 문 제어 화면·저장소·테스트·권한과 Pleos Vehicle SDK 의존성은 제거합니다.
- 키가 없으면 설정 오류를 보여 줍니다. 실제 앱에서 샘플 날씨로 대체하지 않습니다.

## 데이터 정책

| 항목 | 결정 |
|---|---|
| 위치 우선순위 | 현재 위치 → 마지막 저장 위치 → 서울 강남구(37.5172, 127.0473) |
| 위치 제한시간 | 위치 수신 10초. 지역명 조회 실패는 날씨 조회를 막지 않음 |
| 시간 기준 | Asia/Seoul. 좌표는 기상청 5km 격자로 변환 |
| 자료 조합 | 초단기실황 + 초단기예보 + 단기예보 |
| 최고·최저 | 같은 날짜의 공식 TMX/TMN만 사용. 현재 구현은 캐시와 전날 23시 발표로 보완 |
| 결측 | `—` 또는 `정보 없음`. 0도·맑음으로 만들지 않음 |
| 강수량 | `1mm 미만` 같은 범주 보존. 다음 1시간 기준 명시 |
| 확률 | 향후 6시간 내 제공된 예보의 최대 확률. 기준 시간 명시 |
| 캐시 | 격자·자료 종류·발표 시각별 저장, 다른 격자의 자료 혼용 금지 |
| 시작 | 저장된 위치의 캐시를 먼저 관찰하고 현재 위치·최신 자료 확인 |
| 자동 갱신 | 화면이 보일 때 10분마다 위치와 발표 확인. 동일 발표의 성공 응답 재사용 |
| 수동 갱신 | 최신 자료 재조회. 진행 중이면 추가 요청 시작 안 함 |
| 만료 | 실황 2시간 이상 경고, 24시간 초과 기온 제외. 지난 예보 제거 |
| 실패 | 기존 자료 유지, 제품별 실패 구분. 발표 직후 NO_DATA에만 이전 발표 1회 조회 |
| 앱 중단 | 위치·자동 갱신·차량 구독 취소, 복귀 시 재시작 |

발표 경계와 API 오류 코드의 상세 기준은 [기상청 API 문서](kma-contract.md)를 따릅니다.

## 단계별 진행 상태

| 단계 | 계획 | 현재 상태 |
|---|---|---|
| 1. 기반 구성 | 3개 모듈, domain 계약, 수동 DI, 문 제어 정리 | 구현됨. 빌드 확인 |
| 2. 데이터 | 좌표·발표 시각·매핑, Room, 위치 fallback, 오류 정책 | 구현됨. 단위/Room 테스트 통과. 실제 API·위치 통합 미검증 |
| 3. 화면 | ViewModel, Figma 기반 컴포넌트·테마, 상태별 UI | 구현됨. 주·야간/창 크기/오류/주행 화면 테스트 통과 |
| 4. 차량 통합 | Car 초기 상태·콜백, 창 대응, foreground/background | 구현됨. 실제 플랫폼 제한 전환·창 제스처·장시간 백그라운드 미검증 |
| 5. 검증·인계 | 단위 테스트, Lint, APK, 실제 API와 Pleos 종단 간 확인, 문서 | 자동 검증 및 APK 설치·실행 확인. 실제 API 포함 최종 통합 확인 남음 |

## 구현하면서 구체화한 사항

- 넓은 창 기준은 가용 너비 840dp, 낮은 창 기준은 가용 높이 700dp입니다.
- 넓은 창은 6개, 좁은 창은 4개, 간소화 화면은 2개 예보 시점을 선택합니다.
- 실황 유효성·지난 예보는 화면이 보이는 동안 매분 다시 판단합니다. 네트워크 자동 갱신은 10분입니다.
- 조회 후 48시간 지난 캐시를 정리하며 마지막 위치는 한 개만 저장합니다.
- 상태 미확인/차량 연결 해제는 간소화하고 일반 Android의 차량 미지원은 일반 화면으로 구분합니다.
- 사용자 요청에 따라 이미지·아이콘은 Android drawable 리소스로 관리합니다.
  XML로 정상 변환되는 것은 VectorDrawable, 깨지는 것만 원본 기준 2배수 PNG를 사용합니다.
  현재 Figma 아이콘 10개는 모두 XML이며 PNG 대체는 없습니다.

## 남은 완료 조건

- [ ] 유효한 인증키로 실제 기상청 응답과 날씨 표시 확인
- [ ] 실제 위치 변경·권한 회수·서비스 해제·획득 실패의 fallback 확인
- [ ] 실제 조회 후 네트워크 차단 시 캐시와 자료 시각 유지 확인
- [ ] 위치 격자 이동 후 이전 응답이 현재 위치 화면을 덮지 않는지 종단 간 확인
- [ ] 백그라운드에서 위치·갱신 중단, 복귀 후 갱신 확인
- [ ] 프로세스 강제 종료 후 마지막 위치와 날씨 복원 확인
- [ ] Pleos 창 확장/축소 및 실제 CarUxRestrictions 변경 확인

DO 선언과 주행 중 실행 승인은 MVP에서 임의로 확정하지 않습니다. 플랫폼이 실행을 제한하면 따릅니다.
공개 배포 전에는 APK의 인증키 추출 가능성과 배포 정책을 별도로 검토해야 합니다.

실행한 검증의 근거와 미검증 범위는 [검증 기록](verification.md)에 있습니다.
